# rk-essay-final

考前冲刺用。用户给出一个或多个论文押题主题、关键词或真题方向时，基于用户提供或当前工作区配置的项目事实，快速生成可背、可改、可写进正文的论点卡和项目材料。优先读取 `.rk-local/fact-ledger.md`；找不到事实源时先询问路径或要求用户提供材料，不猜测本机绝对路径。

## 边界

- 只生成 `论点卡 + 项目素材 + 背诵句 + 风险提示`，不默认生成完整论文。
- 不虚构新项目；只使用 `论文汇总.md` 已有事实。没有证据的指标标 `[待确认]`。
- 不强套弱匹配题。Serverless、秒杀、边缘计算等与该项目弱相关的题，优先提示风险和替代写法。
- 范文和历年题只能用于分类与结构，不当作官方原题或答案库。

## 工作流

1. 读取用户给出的押题主题；如果主题不完整，按关键词判断。
2. 解析用户提供的事实材料或工作区配置的事实源，提取项目事实、已写专题、可复用结果数据；记录来源位置和事实状态。
3. 读取 [references/topic-router.md](references/topic-router.md) 判断题目类别和适配度。
4. 输出 3 张核心论点卡；每张卡必须包含理论点、项目场景、架构师动作、权衡取舍、结果证据、可背句、跑题提醒。
5. 最后给 `考前背诵建议`：哪些固定背、哪些考场替换、哪些不要写。
6. 使用 [状态协议](../rk-study/references/state-contract.md) 和 [来源协议](../rk-study/references/source-provenance.md) 标注事实状态、来源性质和主题版本。

## 输出格式

对每个主题输出：

- `适配判断`：可写 / 勉强可写 / 不建议硬套。
- `题干义务`：3-5 条，标注落到哪张论点卡。
- `推荐论点卡`：固定 3 张，少于 3 张可辩护材料时不要硬补。
- `项目素材摘取`：列出来自母项目的事实，不超过 6 条。
- `考场替换提醒`：题目关键词、理论模块、结果数据、禁写点。

## 质量检查

- 每张卡都必须体现架构师视角：约束、判断、动作、取舍、结果。
- AI 相关内容只在 AI 测试、智能运维等题目中展开；其他题目最多作为辅助一句。
- 优先复用现有文档中的高可信事实：项目时间、团队规模、接入系统、服务拆分、统一身份、流程集成、上下文继承、Kubernetes、Redis、RabbitMQ、Prometheus/Grafana、测试与性能数据。
- 输出要适合考前记忆：短句优先，避免长篇解释。
- 没有来源位置或仅有计划的内容必须标为 `[待确认]` 或 `计划`，不能写成已实施结果。
