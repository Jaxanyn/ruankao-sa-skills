# rk-essay-template

软考论文模板生成器。

根据题目和项目事实生成考场写作模板，不承诺直接产出合格定稿。

## 工作流

1. 先确认选题方向、项目事实和要套用的格式；用户未提供具体论文题目时，生成通用可替换母版，不强制追问题目原文。
2. 区分用户项目事实、历年真题和范文素材；范文只提取分类、论点和段落结构。
3. 先过输入材料门槛；有题目时用历年真题模式拆出题干义务和四方向归类，无题目时拆方向并生成通用母版；缺少关键项目事实时先补访谈问题。
4. 按摘要、背景、论点卡、项目应用、总结输出可替换模板。
5. 检查题干覆盖、事实一致、近三年项目约束、架构师视角、角色一致和成果不空泛。
6. 若工作区提供 `.rk-local/fact-ledger.md`，先读取事实状态和证据位置；用 [状态协议](../rk-study/references/state-contract.md) 记录模板主题、待确认项和下一次补证任务。

## 输出要求

## 输出载体

默认在聊天中输出模板和检查结果。只有当用户明确要求 `Word`、`docx`、`文档`、`保存到文件`、`导出`，或生成内容较长且适合留档时，才生成文档文件。

生成文档时：

- 优先生成 `.docx`；当前环境不能生成 Word 时，退回生成 Markdown 文件。
- 聊天中只输出文件路径、核心结论、替换卡摘要和下一步建议。
- 文档正文必须包含论文模板、考场替换卡、待确认清单和质量检查。
- 保留一份可复制的 Markdown 或纯文本结构，方便后续用 `/rk-essay` 诊断。

## 追问规则

默认只优先追问 3 类信息：

- `项目时间`：启动、上线、验收或当前阶段，判断是否近三年。
- `关键架构决策`：用户主导或参与的 2-3 个真实决策。
- `真实结果`：上线、验收、性能改善、问题收敛或用户反馈。

不要把 `论文题目原文` 作为生成通用母版的必填项；没有题目时直接保留题目替换位。不要把 `本人角色` 作为必填项；没有角色时默认“系统架构师/架构负责人”，具体主导动作标 `[待本人确认]`。

### 1. 题目拆解

用户给出具体论文题目时，先输出：

- `题目关键词`
- `必须回应的义务`
- `建议选题方向与知识点模块`
- `不适合硬套的部分`
- `四方向覆盖情况`：架构、系统、测试、数据存储中，哪些有项目事实支撑，哪些只保留替换位。

用户没有给出具体论文题目时，不追问“论文题目原文”，改为输出：

- `默认模板方向`
- `可替换题目关键词`
- `通用知识点模块`
- `考场收到题目后必须改写的位置`
- `四方向覆盖情况`：仅把有真实项目事实的方向标为可用，其余标为待补充。

### 2. 项目事实补强

生成模板前必须先判断输入是否过门槛。缺少关键事实时，先给最多 5 个补充问题；不要把“论文题目原文”作为通用模板的必填项。问题只问生成模板真正需要的内容，例如：

- 项目时间、背景、目标；用户要求近三年项目时必须校验时间
- 关键技术点和架构决策
- 真实成果、约束和权衡
- 与题目关键词直接相关的场景

### 3. 主题适配

每次生成模板前都输出 `项目-主题覆盖矩阵`。矩阵至少包含 3 个题目模块、对应项目事实、风险和处理结论。结论只能是：

- `可生成`
- `勉强生成，需标风险`
- `不建议生成，先补事实`

### 4. 模板生成

按用户给定格式输出模板，正文必须保留这些层次：

- 摘要
- 背景介绍
- 理论展开
- 项目应用
- 总结

模板要求：

- 只保留用户事实，缺失处写 `[待本人确认]`
- 用户未提供角色时，默认角色为“系统架构师/架构负责人”；但具体主导动作、决策边界和职责范围仍需标 `[待本人确认]`
- 把可替换位写成明确占位符
- 题目相关理论至少拆成 3 个可展开模块，每个模块都给出项目落点
- 遇到“比较、区别、评估、选择”类题目时，理论模块必须写出比较对象、统一维度、选择理由和项目验证，不可只罗列概念
- 优先从专题论点卡选择 3 个能被用户项目事实支撑的论点，不把所有专题都塞进同一篇
- 不写空泛口号，不把教材定义当论文正文
- 题目不匹配时，直接提示不建议套用
- 理论部分用 `论点卡` 展开，不只写教材定义；每张卡必须包含概念边界、分类或原则、项目落点、架构师动作、权衡和结果验证
- 每个项目应用段都做 `架构师视角检查`：是否写清约束、本人决策或参与动作、取舍理由、验证方式；缺失处标 `[待本人确认]`
- 字数框架是默认模板，不是硬规则；用户给出真题要求时，按题干义务重新分配篇幅

### 5. 考场替换卡

模板结尾必须给出简短替换卡，说明考场上哪些位置要按题目替换，哪些内容只能保留用户真实项目事实，哪些段落不能照搬。

### 6. 质量检查

输出前检查：

- 事实是否前后一致
- 角色是否被写实
- 成果是否可辩护
- 每段是否回应了题干义务
- 是否还有明显的空泛段落

### 7. 证据与状态

- 项目事实使用 `已实施`、`已观察`、`计划`、`待核` 标记；模板正文只把前两类写成已发生事实。
- 指标目标、示范阈值和实测结果分开标识；没有来源的数字保留为替换位。
- 主题、来源和冲突处理遵循 [来源协议](../rk-study/references/source-provenance.md)。

## Completion Criteria

只有在题目拆解、事实补强、主题适配、模板主体和质量检查都完成后结束；如果题目和项目事实不够支撑模板，必须先给补充问题或拒绝硬套。
